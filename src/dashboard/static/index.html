Run details

First token: the prompt's first forward pass (prefill). Decode speed: tokens after the first ÷ their forward-pass time. Private memory: committed by this process; working set: in physical RAM. Peaks are sampled every 0.1 s and can miss shorter spikes. The budget is a target the engine plans against, not an enforced limit. Model output is shown exactly as generated and has not been checked or corrected. Synthetic runs use random weights: their token ids are meaningless.

Comparison details and limits

One run of each mode, one after the other, each from a fresh model load, with the same prompt and settings. Memory-mapped speed depends on what Windows already has in its file cache, so earlier runs and the order affect it; a single comparison is not a benchmark. Memory-mapping keeps weights in the file cache, so its private memory is low while its working set (physical RAM) can be high. The recorded benchmark on the Evidence tab used repeated, alternating runs.

    What these results do and don't show

    Recorded results come from one 8 GB Windows laptop and a few prompts. Output equality was tested for those prompts with greedy decoding; it is not a general correctness guarantee. Timings vary with background load and with Windows' file cache. The engine tests check its mechanisms on a synthetic model, not the real model's quality or speed.
